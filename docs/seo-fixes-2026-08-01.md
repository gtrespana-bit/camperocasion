# 🎯 Plan SEO implementado — 1 de agosto de 2026

Resumen de las correcciones aplicadas según el análisis anterior.

## ✅ PROBLEMAS CRÍTICOS (todos resueltos)

### 1. Inconsistencia de dominio → RESUELTO
- Solo existe `vendet.online`. La home usaba `vende-t.com` en canonical, OG e hreflang.
- Cambiado en `src/app/[locale]/page.tsx` (canonical, languages, OG url, og-image, baseUrl del ItemList JSON-LD).

### 2. Tres robots.txt duplicados → RESUELTO
- Eliminados: `public/robots.txt`, `public/robots.txt.bak`, `src/app/[locale]/robots.ts`.
- **Única fuente**: `src/app/robots.ts` (genera `/robots.txt` con reglas completas incluyendo variantes `/en/`).
- Política deliberada: `/buscar` NO se bloquea (lleva noindex meta; Google necesita rastrearla para ver el noindex).

### 3. Dos sitemaps duplicados → RESUELTO
- Eliminado: `src/app/[locale]/sitemap.ts` (generaba `/es/sitemap.xml` y `/en/sitemap.xml` con URLs hardcodeadas y erróneas como `/dashboard`, `/login`).
- **Único sitemap**: `src/app/sitemap.ts` — estáticas + ciudades + ciudad/categoría + blog (desde `src/content/blog/*.md`, corrige el bug que lo leía de una tabla `blog_posts` inexistente en Supabase) + productos con slug + vendedores activos.

### 4. URLs de productos con UUID → RESUELTO
- **Migración**: `supabase/migrations/024_slugs_productos.sql`
  - Función `slugify()` (sin dependencia de unaccent)
  - Columna `slug` (NOT NULL + índice único) con backfill: `titulo-slugificado-sufijouuid`
  - Trigger BEFORE INSERT para productos futuros
  - RPC `obtener_destacados_home` actualizada para incluir slug
- **App**: `src/lib/product-url.ts` (`productUrl()`, `isUuid()`)
- Página `/producto/[slug]`: resuelve por slug O uuid; si entra por UUID o slug viejo → **301 permanente** al slug canónico (transfiere link equity).
- Links internos actualizados: home, catálogo, búsqueda, landings ciudad/categoría, ProductCard, ProductCardLazy, vendedor, sitemap.
- Ejemplo: `/producto/iphone-13-128gb-impecable-550e8400`

**⚠️ ACCIÓN REQUERIDA**: ejecutar la migración en el SQL Editor de Supabase ANTES de desplegar. El código tiene fallbacks si no existe la columna, pero lo ideal es migración primero.

### 5. Vendedor client-only → RESUELTO
- `src/app/[locale]/vendedor/[id]/page.tsx` ahora es SSR con `generateMetadata()`, ISR (5 min), JSON-LD con `aggregateRating` SOLO si hay reseñas reales, y **404 real** para vendedores inexistentes (antes: redirect 200 vacío = soft 404).
- UI interactiva aislada en `VendedorClient.tsx`.
- Metadatos ricos: nombre + ubicación + "X★ de N reseñas · M productos en venta".

**Nota**: RLS permite lectura pública (`perfiles: USING (true)`, `resenas: USING (true)`), el SSR funciona con la anon key.

### 6. Rating falso en Schema.org → RESUELTO
- Eliminado `src/components/ProductStructuredData.tsx` (no se usaba en ningún sitio) que tenía `ratingValue: '5', reviewCount: '0'`.
- El JSON-LD de producto en `producto/[slug]/page.tsx` no emite aggregateRating (correcto).
- El JSON-LD de vendedor solo emite aggregateRating con reseñas reales de la tabla `resenas`.
